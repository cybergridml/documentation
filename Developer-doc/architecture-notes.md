## Why SysON?

CyberGridML uses **SysON** as the modeling environment for creating and visualizing SysML v2 models through a web-based interface.

By building CyberGridML on SysML v2 concepts rather than on a proprietary modeling language, the models can remain based on a standardized modeling representation. This improves their portability and facilitates their potential use with other SysML v2-compatible tools.

SysON was chosen for several reasons:


* **Web-based modeling** — SysON provides a web-based modeling environment, allowing users to create and work with models directly through a browser.

* **SysML v2 support** — SysON is designed around SysML v2, making it a suitable foundation for implementing the CyberGridML models.

* **Graphical modeling** — SysON allows system architectures to be represented using diagrams, making complex relationships between grid, zone, software, and control elements easier to visualize.

* **Extensibility** — SysON can be extended with domain-specific representations and services. This allows CyberGridML to provide its own nodes, edges, properties, and diagrams.

* **Integration with Eclipse Sirius Web** — SysON is built on the Sirius Web ecosystem, which provides a framework for developing web-based graphical modeling applications.

* **Model-based engineering** — SysON allows the graphical representation to remain connected to the underlying system model, rather than treating diagrams as independent drawings.

* **Integration with CyberGridML** — SysON provides the foundation on which CyberGridML can implement its domain-specific modeling concepts, such as CFA, CRA, CFRA, and Hazards.

In CyberGridML, **SysML v2 defines the modeling language**, while **SysON provides the modeling environment and graphical interface** used to create and visualize the models.
